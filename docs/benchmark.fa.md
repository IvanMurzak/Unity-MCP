# بنچمارک: ابزارهای فشرده در ویرایشگر Unity

بازگشت به [README](README.fa.md).

‏AI Game Developer به جای یک ابزار برای هر کنش، چند ابزار فشرده به عامل می‌دهد که بر پایه **RQL** ساخته شده‌اند؛ RQL یک زبان کوئری روی داده‌های ویرایشگر است. همان کارها را در ویرایشگر واقعی Unity با هر دو کاتالوگ ابزار اجرا کردیم. عامل همان تعداد کار را حل کرد، با **حدود ۵ برابر توکن پرامپت کمتر**، نوبت‌های کمتر و فراخوانی‌های ابزار کمتر، و هر کار را سریع‌تر به پایان رساند. آزمون دوم و بزرگ‌تری روی یک دنیای بازی آزمایشی (sandbox) همین الگو را نشان می‌دهد.

## نتایج ویرایشگر Unity

| معیار | ابزارهای تک‌کنشی | ابزارهای RQL |
| --- | ---: | ---: |
| کارهای حل‌شده (بررسی کار موفق، بدون تغییر ناخواسته) | ⁦۵۹ / ۶۰⁩ | ⁦۵۹ / ۶۰⁩ |
| توکن پرامپت برای هر کار | ⁦۱۳۸٬۲۷۲⁩ | **⁦۲۶٬۰۱۳⁩** |
| توکن تکمیل (completion) برای هر کار | ⁦۶۷۳⁩ | **⁦۳۰۶⁩** |
| نوبت‌های مدل برای هر کار | ⁦۵٫۴⁩ | **⁦۴٫۱⁩** |
| فراخوانی ابزار / خطا برای هر کار | ⁦۵٫۵ / ۰٫۵⁩ | **⁦۳٫۸ / ۰٫۲⁩** |
| حجم نتیجه ابزارها برای هر کار (نویسه) | ⁦۶٬۲۷۳⁩ | **⁦۶۵۷⁩** |
| تعریف‌های ابزار ارسالی همراه هر درخواست (نویسه) | ⁦۹۳٬۱۹۴⁩ | **⁦۲۲٬۴۳۹⁩** |
| زمان کل هر کار | ⁦۸٫۸ s⁩ | **⁦۵٫۴ s⁩** |
| زمان اجرای ابزارها برای هر کار | ⁦۱۶۹ ms⁩ | **⁦۴۲ ms⁩** |
| هزینه هر کار | ⁦۱×⁩ | **حدود ⅓** |

‏**چرا ارزان‌تر است.** بیشتر این فاصله از دو جا می‌آید: تعریف‌های ابزاری که عامل همراه هر درخواست دریافت می‌کند ۴٫۲ برابر کوچک‌ترند، و نتایج ابزارها ۹٫۵ برابر کوچک‌ترند. در کارهای انبوه و کوئری، کاتالوگ تک‌کنشی به نوشتن کد C# روی آورد (`script-execute` در مجموع همه اجراها ۶۸ بار، در برابر ۷ بار با RQL)؛ با RQL عامل به جای آن یک کوئری می‌نویسد.

‏**اجرای کنترلی.** پس از مهاجرت افزونه‌ها و اصلاحات هسته (undo زنجیره‌های مالک، مسیرهای دارایی، `unity.find`، قالب‌بندی اعداد)، کاتالوگ RQL ‏**۶۰ / ۶۰** کار را با ۲۳٬۲۷۴ توکن پرامپت، ۳٫۴ فراخوانی ابزار و ۴٫۸ ثانیه برای هر کار حل کرد.

## نتایج دنیای بازی آزمایشی

پروژه RQL خود زبان را جدا از Unity اندازه می‌گیرد: یک دنیای بازی تولیدشده و عاملی که یا از RQL استفاده می‌کند یا از ابزارهای ساده‌ی reflection ‏(`find_objects`، `get_object` به صورت خروجی JSON، `describe_type`، `set_value`، `call_method`). تمیزترین بررسی از ۳۰ کار جدید استفاده کرد که پس از ثابت شدن همه تنظیمات نوشته شدند و یک بار اجرا شدند، هر کار ۳ بار.

## روش‌شناسی

‏**ویرایشگر Unity.** اندازه‌گیری روی Unity-MCP 0.93.4 (همه ابزارهای فعال، یک ابزار برای هر کنش: `gameobject-*`، `assets-*`، `scene-*`، `object-*`، `console-get-logs`، `script-execute`، `tests-run`، …) در برابر کاتالوگ RQL ‏(`rql-query`، `rql-mutate`، `rql-schema`، `script-execute`، `tests-run`، `screenshot-isolated`، `unity-tool-list`). هارنس، صحنه و مدل برای هر دو یکسان: `deepseek-flash`، استدلال (reasoning) خاموش، temperature برابر ۰. ‏۲۰ کار × ۳ اجرا، Unity 6000.6.4f1. هر حالت دقیقاً همان ابزارهایی را گرفت که یک کلاینت MCP می‌بیند، با نام‌ها، توضیحات و اسکیمای ورودی خودشان، و از طریق پلاگین فراخوانی شدند. یک کار فقط زمانی موفق است که بررسی آن موفق شود و هیچ چیز دیگری در صحنه تغییر نکرده باشد.

‏**دنیای بازی آزمایشی.** کارها، ارزیاب، مدل و بودجه برای هر دو مجموعه ابزار یکسان است؛ فقط ابزارها فرق دارند. مدل DeepSeek V4.1-Flash، حداکثر ۱۲ گام برای هر کار، ۳ اجرا برای هر کار. یک ارزیاب پنهان پاسخ مورد انتظار را مستقل محاسبه می‌کند؛ کارهای تغییردهنده با هر تغییر ناخواسته شکست می‌خورند. کارهای کنارگذاشته هرگز برای تنظیم استفاده نشدند؛ مجموعه دوم کارها پس از ثابت شدن تنظیمات نوشته شد و یک بار اجرا شد.

## محدودیت‌ها

- ‏**یک خانواده مدل.** هر دو آزمون از مدل‌های DeepSeek استفاده کردند. مدل‌های دیگر ممکن است اعداد متفاوتی نشان دهند.
- ‏**نسخه‌های اندازه‌گیری‌شده.** اعداد ویرایشگر Unity نسخه Unity-MCP 0.93.4 را با کاتالوگ RQL روی یک صحنه و یک نسخه Unity مقایسه می‌کنند؛ ابزارها و مدل‌ها با گذشت زمان تغییر می‌کنند.
- ‏**نمونه‌های کوچک.** ۶۰ اجرا برای هر حالت در ویرایشگر؛ ۸۱ تا ۹۰ اجرا برای هر حالت در نتایج دنیای بازی آزمایشی بالا.
- ‏**نویسنده یکسان.** کارهای RQL و دنیای بازی آزمایشی را نویسنده خود زبان طراحی کرده است. کارهای کنارگذاشته و مجموعه کارهایی که پس از تنظیم نوشته شد این سوگیری را کاهش می‌دهند، اما از بین نمی‌برند.
- ‏**هزینه یک نسبت است.** کش پرامپت (prompt caching) باعث می‌شود هزینه تا حدی به ترافیک دیگر وابسته باشد؛ تعداد توکن‌ها و فراخوانی‌های ابزار نشانه‌های پایدارتری هستند.
