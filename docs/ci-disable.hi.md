# CI में Unity-MCP अक्षम करें

core **1.6.2** और फ़र्स्ट-पार्टी एक्सटेंशन **2.1.1** में पेश किया गया।

ये स्वतंत्र ऑप्ट-आउट UPM मैनिफ़ेस्ट को अपरिवर्तित छोड़ते हैं। इनमें से कोई भी `-batchmode` या `-runTests` के लिए
स्वचालित रूप से सक्षम नहीं होता: हेडलेस MCP सत्रों और MCP के अपने टेस्ट को अभी भी प्लगइन की ज़रूरत होती है।

## विकल्प 1: इनिशियलाइज़ेशन छोड़ें (सामान्य CI टेस्ट के लिए अनुशंसित)

**Unity लॉन्च करने से पहले** प्रोसेस एनवायरनमेंट वेरिएबल सेट करें:

```bash
UNITY_MCP_DISABLE=1 "$UNITY_EDITOR" -batchmode -nographics \
  -projectPath "$PROJECT_PATH" -runTests -testPlatform PlayMode \
  -testResults "$PROJECT_PATH/test-results.xml" -logFile -
```

GitHub Actions में, `UNITY_MCP_DISABLE: '1'` को उस स्टेप की `env` मैपिंग में रखें जो
Unity लॉन्च करता है। Docker रनर के लिए, इसे स्पष्ट रूप से Unity कंटेनर में फ़ॉरवर्ड करें, उदाहरण के लिए
`docker run --env UNITY_MCP_DISABLE=1 ...`। इसे केवल होस्ट पर सेट करने से यह ज़रूरी नहीं कि
किसी action के कंटेनर तक पहुँचे।

`1` और `true` (केस-असंवेदनशील, आसपास के व्हाइटस्पेस को अनदेखा किया जाता है) MCP को अक्षम करते हैं। सेट न होना, `0`,
`false`, और अपरिचित मान सामान्य व्यवहार बनाए रखते हैं। इसे बदलने के बाद Unity को पुनः आरंभ करें।
यह एक प्रोसेस ओवरराइड है और प्रोजेक्ट सेटिंग्स में सहेजा नहीं जाता।

MCP अपना स्टार्टअप, टूल रजिस्ट्रेशन, टेस्ट-रनर कॉलबैक, बैकग्राउंड सर्वर डाउनलोड/स्टार्ट,
NuGet डिपेंडेंसी रिज़ॉल्यूशन, लॉग संग्रह और editor/PlayMode हुक छोड़ देता है। इसके सोर्स फिर भी कंपाइल होते हैं
और असेंबली फिर भी लोड हो सकती हैं। इसलिए मौजूदा प्रोजेक्ट डिपेंडेंसी मान्य होनी चाहिए; यह मोड
गायब DLL या कंपाइलेशन एरर का समाधान नहीं है। अक्षम होने के दौरान स्पष्ट रनटाइम इनिशियलाइज़ेशन
एक एक्सेप्शन रिपोर्ट करता है। जो जॉब जानबूझकर MCP का परीक्षण करते हैं, उनके लिए वेरिएबल हटा दें।

## विकल्प 2: MCP सोर्स असेंबली को कंपाइलेशन से बाहर रखें

अपने CI जॉब में उपयोग होने वाले हर बिल्ड टार्गेट के लिए, **Project Settings > Player > Other Settings** के अंतर्गत
Unity के **Scripting Define Symbols** में **`UNITY_MCP_EXCLUDE_FROM_COMPILATION`** जोड़ें।
अन्य सिंबल बनाए रखें। यह एक स्क्रिप्टिंग सिंबल है, **एनवायरनमेंट वेरिएबल नहीं**।

CI के लिए, Unity शुरू करने से पहले परिणामी `ProjectSettings/ProjectSettings.asset` तैयार करें
(उदाहरण के लिए, CI-विशिष्ट सेटिंग्स की एक प्रति का उपयोग करें)। यदि डेवलपर्स को MCP चाहिए, तो सामान्य डेवलपमेंट सेटिंग्स
इस सिंबल के बिना रखें। इसे उसी टेस्ट रन में `-executeMethod` से सेट न करें:
वह पहले कंपाइलेशन के बाद होता है और defines बदलने से एक और कंपाइलेशन शुरू हो जाता है।

सभी core पैकेज असेंबली (डिपेंडेंसी रिज़ॉल्वर, runtime, editor, RQL मॉड्यूल
और पैकेज टेस्ट सहित), साथ ही अपडेट की गई फ़र्स्ट-पार्टी एक्सटेंशन असेंबली, नकारात्मक असेंबली
constraint `!UNITY_MCP_EXCLUDE_FROM_COMPILATION` का उपयोग करती हैं। यह सिंबल उन असेंबली को एक साथ बाहर कर देता है।
हर इंस्टॉल किए गए MCP एक्सटेंशन को भी ऐसी रिलीज़ पर अपडेट करें जिसमें यह constraint हो; पुरानी रिलीज़
और थर्ड-पार्टी एक्सटेंशन अभी भी बाहर की गई core असेंबली को रेफ़रेंस कर सकते हैं। MCP टाइप्स को रेफ़रेंस करने वाले
कस्टम कोड को मेल खाते constraints या `#if !UNITY_MCP_EXCLUDE_FROM_COMPILATION` का उपयोग करना होगा।

यह MCP C# सोर्स असेंबली को बाहर करता है। यह UPM पैकेज अनइंस्टॉल नहीं करता, इम्पोर्ट किए गए assets नहीं हटाता,
और अन्य पैकेजों के साथ साझा प्रीकंपाइल्ड DLL को न हटाता है न अक्षम करता है। सिंबल हटाने से सामान्य
कंपाइलेशन बहाल हो जाता है। मोड बदलने से Unity का कंपाइलेशन कैश अमान्य हो सकता है; बाहर किए गए और सामान्य जॉब के लिए
अलग CI कैश कुंजियाँ रखें। इस मोड में विकल्प 1 का एनवायरनमेंट वेरिएबल अनावश्यक है।
