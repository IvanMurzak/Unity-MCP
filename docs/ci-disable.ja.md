# CI で Unity-MCP を無効にする

core **1.6.2** およびファーストパーティ拡張 **2.1.1** で導入されました。

これらの独立したオプトアウトは UPM マニフェストを変更しません。どちらも `-batchmode` や `-runTests` で
自動的に有効になることはありません。ヘッドレスの MCP セッションや MCP 自身のテストには引き続きプラグインが必要だからです。

## 方法 1: 初期化をスキップする (通常の CI テストに推奨)

**Unity を起動する前に**プロセス環境変数を設定します:

```bash
UNITY_MCP_DISABLE=1 "$UNITY_EDITOR" -batchmode -nographics \
  -projectPath "$PROJECT_PATH" -runTests -testPlatform PlayMode \
  -testResults "$PROJECT_PATH/test-results.xml" -logFile -
```

GitHub Actions では、Unity を起動するステップの `env` マッピングに `UNITY_MCP_DISABLE: '1'` を
記述します。Docker ランナーの場合は、Unity コンテナーに明示的に転送してください。例:
`docker run --env UNITY_MCP_DISABLE=1 ...`。ホスト側だけで設定しても、アクションのコンテナーに
渡されるとは限りません。

`1` と `true` (大文字小文字を区別せず、前後の空白は無視) で MCP が無効になります。未設定、`0`、
`false`、および認識されない値では通常の動作が維持されます。変更後は Unity を再起動してください。
これはプロセス単位のオーバーライドであり、プロジェクト設定には保存されません。

MCP は起動処理、ツール登録、テストランナーのコールバック、バックグラウンドでのサーバーのダウンロード/起動、
NuGet 依存関係の解決、ログ収集、エディター/PlayMode のフックをスキップします。ソースは引き続きコンパイルされ、
アセンブリも読み込まれ得ます。そのため既存のプロジェクト依存関係は有効である必要があり、このモードは
DLL の欠落やコンパイルエラーの回避策にはなりません。無効化中に明示的なランタイム初期化を行うと例外が
報告されます。意図的に MCP を動かすジョブでは、この変数を削除してください。

## 方法 2: MCP のソースアセンブリをコンパイル対象から除外する

ビルドターゲットごと (CI ジョブで使うすべて) に、**Project Settings > Player > Other Settings** の
Unity の **Scripting Define Symbols** へ **`UNITY_MCP_EXCLUDE_FROM_COMPILATION`** を追加します。
他のシンボルは残してください。これはスクリプティングシンボルであり、**環境変数ではありません**。

CI では、Unity を起動する前に、このシンボルを含む `ProjectSettings/ProjectSettings.asset` を用意します
(例: CI 専用の設定のコピーを使う)。開発者が MCP を必要とする場合、通常の開発用設定はこのシンボルなしの
ままにしてください。同じテスト実行内の `-executeMethod` から設定しないでください。それは最初のコンパイルの
後に行われ、define の変更が再コンパイルを引き起こします。

すべての core パッケージのアセンブリ (依存関係リゾルバー、ランタイム、エディター、RQL モジュール、
パッケージのテストを含む) と、更新されたファーストパーティ拡張のアセンブリは、否定のアセンブリ
制約 `!UNITY_MCP_EXCLUDE_FROM_COMPILATION` を使用します。このシンボルはそれらのアセンブリをまとめて除外します。
インストール済みのすべての MCP 拡張も、この制約を含むリリースに更新してください。古いリリースや
サードパーティの拡張は、除外された core アセンブリを引き続き参照している場合があります。MCP の型を参照する
カスタムコードは、対応する制約か `#if !UNITY_MCP_EXCLUDE_FROM_COMPILATION` を使う必要があります。

これは MCP の C# ソースアセンブリを除外します。UPM パッケージのアンインストール、インポート済みアセットの削除、
他のパッケージと共有されるプリコンパイル済み DLL の削除/無効化は行いません。シンボルを削除すると通常の
コンパイルに戻ります。モードを切り替えると Unity のコンパイルキャッシュが無効になることがあるため、除外ジョブと
通常ジョブで CI のキャッシュキーを分けてください。このモードでは方法 1 の環境変数は不要です。
