**AI Game Developer** (Unity-MCP) connects your AI agent to Unity. Claude Code, Codex, Cursor, GitHub Copilot, Gemini or any other [MCP](https://modelcontextprotocol.io/) client can read and change scenes, prefabs, assets and C# code, run tests and take screenshots in the **Unity Editor**, and call tools you write **inside your compiled game**. It ships as a free Unity package (`com.ivanmurzak.unity.mcp`), a command-line tool (`unity-mcp-cli`) and optional extensions.

**Status:** [latest release](https://github.com/IvanMurzak/Unity-MCP/releases/latest) and [changelog](https://github.com/IvanMurzak/Unity-MCP/blob/main/Unity-MCP-Plugin/Packages/com.ivanmurzak.unity.mcp/CHANGELOG.md). The plugin and `unity-mcp-cli` share one version. Tested and supported on **Windows, macOS and Linux**. Requires Unity **2022.3** or newer; CI runs EditMode, PlayMode and standalone-build tests on Unity 2022.3, 6000.0, 6000.3 and 6000.6.

## How it works

<p align="center"><img src="https://raw.githubusercontent.com/IvanMurzak/Unity-MCP/main/docs/img/readme/architecture.svg" alt="An AI agent or unity-mcp-cli talks MCP to a server, ai-game.dev Cloud by default or a local gamedev-mcp-server, which calls the tools of the Unity Editor plugin and of your running game" width="100%"></p>

The plugin registers its tools with an MCP server; your agent calls them through that server. Instead of MCP tools, the agent can also use generated **Skills**. You choose where the server runs:

| | **Local** (Custom mode, no account) | **Cloud** (default setting) |
| --- | --- | --- |
| Server | [GameDev-MCP-Server](https://github.com/IvanMurzak/GameDev-MCP-Server) started by the plugin on `127.0.0.1`, or one you host | `https://ai-game.dev/mcp` |
| Account | Not needed | Sign in to ai-game.dev |
| Your project data | Stays on your machine | Tool calls pass through a stateless relay that does not inspect or persist their contents; it records MCP event metadata, used within a rolling 90-day window ([Privacy Policy](https://ai-game.dev/legal/privacy)) |
| Cost | Free | Free |

**Why Cloud is the default:** it needs no open ports and avoids port conflicts with other programs, and it is free. Local is an equal option for offline or air-gapped work. Details: [Security and privacy](#security-and-privacy).

## Features

✅ **Covers the Editor** — the agent can do virtually anything you can do in the Unity Editor\
✅ **Compact and efficient** — tools built for agents: fewer calls and fewer tokens, so the agent works faster and cheaper ([measured in the Unity Editor](https://github.com/IvanMurzak/Unity-MCP/blob/main/docs/benchmark.md))\
✅ **RQL** — read and change scenes, objects, assets and settings with one query language\
✅ **C# and tests** — compile and run C# with Roslyn; run EditMode and PlayMode tests\
✅ **Skills or MCP** — generate Skills in one click, or connect as an MCP client\
✅ **Any agent** — Claude Code, Codex, Cursor, Copilot, Gemini and other MCP clients\
✅ **Runtime** — the same tools inside your built game: NPC logic, live debugging\
✅ **Your own tools** — any C# method becomes a tool with one `[AiTool]` attribute\
✅ **CLI** — install, open, query, compile and test from the terminal or CI\
✅ **Extensions** — optional tool packs, from Animation to Timeline

## Quick start

Requires **Unity 2022.3** or newer.

**1. Install the plugin** (recommended: the Installer, nothing else to install):

[![DOWNLOAD INSTALLER](https://raw.githubusercontent.com/IvanMurzak/Unity-MCP/main/docs/img/button/button_download.svg)](https://github.com/IvanMurzak/Unity-MCP/releases/latest/download/AI-Game-Dev-Installer.unitypackage)

Open the downloaded `.unitypackage` with your project open (double-click it, or **Assets ▸ Import Package ▸ Custom Package**).

<details>
<summary>Other ways to install: OpenUPM / Package Manager, or the CLI for scripting and CI</summary>

- **OpenUPM** — `openupm add com.ivanmurzak.unity.mcp`, or without any CLI: add a scoped registry in **Edit ▸ Project Settings ▸ Package Manager** (URL `https://package.openupm.com`, scopes `com.ivanmurzak` and `extensions.unity`), then **Window ▸ Package Manager ▸ + ▸ Add package by name** → `com.ivanmurzak.unity.mcp`.
- **unity-mcp-cli** (Node.js 22.14+) — for scripts and CI, no Editor needed:

  ```bash
  npm install -g unity-mcp-cli
  unity-mcp-cli install-plugin ./MyUnityProject   # add the plugin to Packages/manifest.json
  unity-mcp-cli open ./MyUnityProject             # open the project in Unity
  ```

</details>

**2. Connect your agent** — pick one; both are fully supported:

| | **Local** (no account) | **Cloud** (default setting) |
| --- | --- | --- |
| In **Window ▸ AI Game Dev** | connection **Custom** | connection **Cloud**, then **Authorize** (browser sign-in) |
| Agent config | **Configure** for your agent | **Configure** for your agent |
| Same from the CLI | `unity-mcp-cli setup-mcp claude-code ./MyUnityProject --transport stdio` | `unity-mcp-cli login`, then `unity-mcp-cli setup-mcp claude-code ./MyUnityProject` |

**Auto-generate** Skills in the same window is the alternative to MCP. Other agents: [client setup](#client-setup).

**3. Local only: choose who may call your tools.** The local server starts with auth `none`: it listens only on `127.0.0.1` and rejects foreign browser origins, but any program on your machine can reach it. If other people or untrusted programs use the machine, switch to `token` in one step: **Window ▸ AI Game Dev** → **Authorization Token** → `token`. The server restarts with a generated secret; press **Configure** again so your agent sends it.

## Usage

**Talk to your agent.** Describe the result you want; the more precise, the better.

```text
Explain my scene hierarchy
Create metallic golden material and attach it to a new sphere
Find every enemy prefab without a Rigidbody and add one
```

**What your agent can do** (tools shown by default):

| Capability | Tool | Example prompt |
| --- | --- | --- |
| Scenes and GameObjects | `rql-query`, `rql-mutate` | *"List every disabled GameObject in the open scene"* |
| Assets and prefabs | `rql-query`, `rql-mutate` | *"Create a red material and assign it to all cubes"* |
| Console and Editor state | `rql-query` | *"What errors are in the console?"* |
| C# in the Editor | `script-execute` | *"Run C# that places 100 trees at random points on the terrain"* |
| Tests | `tests-run` | *"Run the EditMode tests and fix what fails"* |
| Screenshots | `screenshot-isolated` | *"Show me the Player model from the front"* |
| Packages and Asset Store | `package-*`, `assetstore-*` | *"Install Cinemachine"* |
| Tool list | `unity-tool-list` | *"Which tools can you use here?"* |

You do not learn RQL: the agent writes it and asks `rql-schema` for every source, type and call it needs. Measured in the Unity Editor: the same tasks took about 5× fewer prompt tokens and fewer tool calls than one-tool-per-action tools, at the same success rate ([benchmark](https://github.com/IvanMurzak/Unity-MCP/blob/main/docs/benchmark.md)). On a sandbox game world, with RQL an agent needs about 2–3 tool calls and 7–8k tokens per task at 100% success, versus 30–37 calls and 125–170k tokens at 67–91% success with plain reflection tools ([results](https://github.com/IvanMurzak/RQL/blob/main/RESULTS.md#33-rql-vs-conventional-reflection-tools)). More tools are installed but hidden until you show them. Full list: **[Default MCP tools](https://github.com/IvanMurzak/Unity-MCP/blob/main/docs/default-mcp-tools.md)** or [ai-game.dev/docs/tools](https://ai-game.dev/docs/tools).

**From the terminal** (starts a headless editor when none is running):

```bash
unity-mcp-cli rql 'objects | where name starts-with "Tree" | count'
unity-mcp-cli compile ./MyGame
unity-mcp-cli test ./MyGame --mode PlayMode
```

**Your own tool.** A class with `[AiToolType]` and a method with `[AiTool]` is all it takes:

```csharp
[AiToolType]
public class Tool_Score
{
    [AiTool("score-reset", Title = "Reset the score")]
    [Description("Sets the player's score to zero.")]
    public string Reset()
    {
        return MainThread.Instance.Run(() =>
        {
            ScoreManager.Instance.Score = 0;
            return "[Success] Score reset.";
        });
    }
}
```

Prompts, runtime (in-game) tools and a full example: **[Custom tools and runtime](https://github.com/IvanMurzak/Unity-MCP/blob/main/docs/custom-tools.md)**.

## Client setup

The **Configure** button in the AI Game Developer window, or `unity-mcp-cli setup-mcp <agent> ./MyUnityProject`, writes these files for you (Cloud by default, local with `--transport stdio`). By hand, for a local server: set the plugin to **Custom**, take `<port>` from the window, and use the binary for your platform from `<project>/Library/mcp-server/<rid>/` (`win-x64/gamedev-mcp-server.exe`, `osx-arm64/gamedev-mcp-server`, `linux-x64/gamedev-mcp-server`, …).

<details>
<summary><b>Claude Code</b> — <code>.mcp.json</code> in the project root</summary>

```json
{
  "mcpServers": {
    "ai-game-developer": {
      "command": "<project>/Library/mcp-server/win-x64/gamedev-mcp-server.exe",
      "args": ["port=<port>", "client-transport=stdio"]
    }
  }
}
```

</details>

<details>
<summary><b>Cursor</b> — <code>.cursor/mcp.json</code></summary>

```json
{
  "mcpServers": {
    "ai-game-developer": {
      "type": "stdio",
      "command": "<project>/Library/mcp-server/win-x64/gamedev-mcp-server.exe",
      "args": ["port=<port>", "client-transport=stdio"]
    }
  }
}
```

</details>

<details>
<summary><b>Codex</b> — <code>.codex/config.toml</code></summary>

```toml
[mcp_servers.ai-game-developer]
enabled = true
command = "<project>/Library/mcp-server/win-x64/gamedev-mcp-server.exe"
args = ["port=<port>", "client-transport=stdio"]
tool_timeout_sec = 300
```

</details>

## Security and privacy

**Most private setup:** connection **Custom** (local server on `127.0.0.1`, no account, project data stays on your machine) with **Authorization Token** set to `token` in **Window ▸ AI Game Dev**, then **Configure** again so your agent sends the secret.

✅ **The plugin opens no port** — it connects out to the MCP server.\
✅ **Local server on loopback** — `gamedev-mcp-server` binds to `127.0.0.1` unless you set `MCP_BIND` for hosting.\
✅ **Origin checks** — browser requests with a non-allowed `Origin` are rejected (403) in every auth mode.\
✅ **Auth modes** — `none` (local default), `token` (one shared secret the agent and the plugin must both send), `oauth` (ai-game.dev account).\
✅ **Cloud relay** — a stateless relay: it routes tool calls between your agent and the Editor without inspecting or persisting their contents, and does not collect conversations, source code, project files, assets or scene data. It records MCP event metadata (event type, timing, status, session identifiers, the tool, prompt or resource name, error details), used within a rolling 90-day window ([Privacy Policy](https://ai-game.dev/legal/privacy)).\
⚠️ **Not protected** — in `none` mode any process on your machine that reaches the port can call tools, and tools run with Editor rights (`script-execute` runs C#). Use `token` mode on shared machines.

Server options and Docker: [MCP server and connection](https://github.com/IvanMurzak/Unity-MCP/blob/main/docs/mcp-server.md).

```bash
unity-mcp-cli install-extension com.ivanmurzak.unity.mcp.cinemachine ./MyUnityProject
```

| [ProBuilder](https://github.com/IvanMurzak/Unity-MCP/blob/main/extensions/ProBuilder/README.md) | Editable meshes: shapes, extrude, bevel, materials | `com.unity.probuilder` 5.2.4+ |
